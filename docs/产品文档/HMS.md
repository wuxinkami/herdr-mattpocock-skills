# HMS 角色调度设计

HMS（`herdr-mattpocock-skills`）按工作性质选择 agent、模型和思考等级，安排执行会话并把结果送回发起者。模型自己的开发计划和 Matt 技能都能使用 HMS。工作内容、依赖、并行度、上下文要求和完成标准沿用当前工作流。

## 启用与配置

用户在主会话明确引用并启用 HMS 后，该会话持续担任秘书。项目路由可以事先配置，单独使用 Matt 技能仍按该技能执行。在已启用的主会话里点名技能时，秘书将任务派给对应身份。用户直接在负责工作的面板讨论细节，也可以通过秘书向一个或多个成员转达指令。

开工前，用户可在身份表为任意身份填写一个或多个本轮技能，包含稍后才会派工的身份。每阶段只核对新增或变更的行。秘书或 PM 开窗口时，脚本把接收身份选定的每项技能以 `$技能名` 写入首条任务消息。用户明确要求保存时由 setup 写入该身份的项目默认值。

HMS 和 `herdr-setup` 在仓库的 `skills/` 下平级，共用安装器。常见 CLI 的[适配模板](../../skills/herdr-setup/templates/routing.json)归 setup 管理，Gemini 使用 `agy`，DSH 使用 `dst`。setup 展示项目 `.agents/herdr/routing.json` 中已有身份的 CLI、模型和思考等级，缺少的身份留空。用户只补填用到的身份或指明要调整的字段，setup 将答复合并到现有配置。新增身份的思考等级留空时用 `high`。主会话沿用自身设置。

HMS 日常读取项目激活配置。临时换 CLI 时沿用项目为该 CLI 填过的唯一型号。有多个或没有具体型号时问一次，用户可明确选 `default`。团队中途新增身份或更换配置时只补确认变化项，用户亲自点名即为确认。工具各入口的选型方式归 [setup 参数参考](../../skills/herdr-setup/references/cli-options.md)。

## 身份与委托

| 身份 | 会话与职责 |
| --- | --- |
| 秘书 `secretary` | 用户启用 HMS 的主面板。传达和广播用户指令、调度对应成员、汇总回报。 |
| 需求对齐 `grill` | 显式面板承接 grilling、Wayfinder、规格和拆票。同一需求的访谈、写规格和拆票可以在同一条对话继续。 |
| 原型 `prototype` | 显式面板，独立配置。秘书或 PM 可以直接派原型。一张 Wayfinder 原型票在同一面板体验、确认并写回 map。 |
| PM `pm` | 唯一显式 PM。按用户选定的 `implement` 或 `implement-spec` 调度实现者，在用户授权范围内审批或合并，回报秘书。 |
| 前端 `frontend` | 负责本票前端代码。 |
| 后端 `backend` | 负责本票后端代码。 |
| 搜索 `searcher` | 匿名，匹配搜索、代码探索和 research。使用 Matt 时，调查内容与产物由相应技能决定。 |
| 审查 `reviewer` | 匿名，匹配评审。评审视角、所需的独立上下文及返回内容由当前工作流决定。 |
| 方案设计 `designer` | 按需匿名。为工作流要求的独立方案选择模型，方案数量和比较方式由该工作流决定。 |
| 合并 `merger` | 普通已授权合并可由 PM 自行执行。工作流要求独立合并者时，PM 调独立的 merger，按该流程要求的会话形态执行。 |

匿名身份仅在同工具同模型、宿主能落实等级、工作目录和所需上下文时走原生 subagent。换工具、换型号或宿主能力不足时按原流程用相应的无头 CLI。

## 按票执行

团队模式由 PM 分票。没有正式工单时，PM 可以按当前开发计划中的任务派组。

| 本票的工作 | PM 派出的执行者 | 主实现者 |
| --- | --- | --- |
| 只有前端 | 前端 | 前端 |
| 只有后端 | 后端 | 后端 |
| 跨前后端 | 同一票的一名前端和一名后端 | 该票的后端 |

例如，10 张跨端票共用一个 PM，每票各有一名前端和一名后端。可同时推进哪些票由依赖决定。Matt 的 `implement-spec` 要求每票使用新的实现者上下文、独立的 worktree 和分支。fresh 实现者按项目对应端的型号与等级开新面板。跨端在同一票级 worktree 依序交接，整体交独立 merger。纯前端票由前端主责。

需求访谈结束后保留原面板。用户接着要求写规格、拆票时，由原 agent 与用户核对测试切入点、工单拆分及依赖，并把已发布的规格和工单入口回报秘书。秘书请用户选择按票实施、整组实施或收尾，按答复安排 PM。

需要跨会话规划时，由 `grill` 用 Wayfinder 建图，发出所需 research 后停下。用户要求推进时，每张普通决策票开新的 `grill` 面板，每张原型票开新的 `prototype` 面板。派工带技能、map 和票，用户直接在票面板参与决定。整图收敛后由 `grill` 读取主 map 和关联结论，依序完成用户要求的规格与拆票。

## 面板、回报和记录

- `SKILL.md` 提供 HMS 的技能路由、命令和团队登记约定。派工正文附本轮配置的 `ctx:…` 短 ID、回报命令和该文件的路径。每次更新配置返回新 ID，原 ID 仍指向原快照。`herdr-setup` 只写项目路由配置。适配 Matt 的身份由对应技能确定工作内容。
- 每个需要派工的 agent 都可以调用 HMS。脚本核对发起面板的 Herdr 会话，在同一工作区和标签页分屏，随任务传递任务标识、HMS 入口和发起者的回报地址。地址绑定 Herdr socket 与终端。恢复后，团队回报按已核实的原生会话重新绑定发起者。
- 面板地址使用 `hms:…` 短 ID。两类短 ID 都在当前账号的 `${XDG_STATE_HOME:-~/.local/state}/hms/refs/` 解析，同一账号下各宿主和 worktree 共用。现有 Base64 参数仍可读取，后续派工和配置更新返回短 ID。
- 团队回报核对任务和身份后先写入 SQLite，再投递给发起者。发起者等待审批时最多等一分钟。重发相同回报复用库内记录，Herdr 确认投递后写入送达时间。原生 subagent 由宿主接收返回值，无头 CLI 输出直返。
- 发起者判断任务完成，等其成员结束回合后关闭相应面板。借用面板保留，明确移交管理后由负责人收尾。
- 团队模式在主项目 `.agents/herdr/state/hms.sqlite3` 保存轮次、任务、每次派工的短 `run:…` ID 和结果。同一任务可以保留多次执行。显式运行的启动结果、业务状态和面板信息分别记录。
- 每轮的 `.agents/herdr/session/<时间戳>-<recap标题>.md` 是供用户查看的索引，显示轮次 ID、秘书恢复命令和五列成员表。显式成员在 Herdr 观察到首条任务活动并取得原生会话 ID 后进入索引，匿名 CLI 还须成功退出。实际模型或等级查不到写“未核实”。旧团队表首次使用时原路径导入，保留有效会话并过滤“未取得”。
- 重启后在 Herdr 中按索引打开秘书，运行 `hms recover --round R`。HMS 核对原生会话 ID，复用在线 worker，恢复未完成的 Codex 和 Claude 会话，并返回待处理的回报。秘书根据执行记录续发任务。只有成员信息的历史记录可以手动恢复对应会话。
