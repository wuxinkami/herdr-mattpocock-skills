# 路由约定

## 配置快照

以本轮秘书展示、用户确认并归档的配置为执行依据。已有 `routing.json` 是唯一的本地默认配置，不与模板混合补字段；本轮临时指定不自动写回默认值。设计阶段使用已选设计职责配置，进入实现仍须由秘书统一确认。

接收端读取交接中的配置快照和已解析的外部技能，只执行分配阶段，不能重新用本地默认值覆盖，也不能再次启动完整团队。PM 只核对已有确认；缺少确认时返回秘书，不自行向用户发起新的开工表。

简单模式合并 `simple.main.roles` 中的身份，使用主会话实际工具、模型和思考等级；未合并身份使用对应 `roles` 条目。要让简单模式 searcher 独立匿名运行，从 `simple.main.roles` 移除 searcher 并确认其独立配置即可，显式窗口数量不因此增加。merger 的继承对象是最终有效 PM，不只是配置文件里未经解析的 `roles.pm`。

## 一次派工的输入

- 身份、任务标识与标题、项目及工作目录。
- 外部技能的实际名称、已解析的 `SKILL.md` 绝对路径或宿主资源标识、已知版本，以及当前阶段是协调者还是叶执行者。接收端按 [外部技能约定](matt.md) 验证可读性；必要资源沿原技能的相对路径读取。
- spec、ticket、依赖答案、代码范围和必要用户决定的入口。
- 允许修改的范围、Git 决策归属、所需返回结果及完成条件。
- 已确认的配置快照、归档路径、父会话的真实 Herdr 地址与回报方式。

传文档和必要约束，不复制父会话整段对话。上游只有一个实现单元时不任意碎拆；上游已有多个单元时沿其图派发。一个纵向 ticket 涉及前后端时，PM 可安排各一名相应 worker，分别拥有完整职责范围，并共享接口约定，不另造一套水平 tickets。

## 显式执行与生命周期

1. 按 [工具适配](tools.md) 核实本机接口与角色配置。秘书必须先归档用户确认，才能创建实施 PM；设计 griller 按设计队列运行。
2. 创建目标工作目录中的 Herdr 面板，从返回值取得真实位置，再启动已选工具；核实就绪后发送派工内容。当前秘书不另行复制。
3. 获取原生 session ID，写入 [台账](session-record.md)。pane ID、PID 或角色名不能冒充它；取不到时如实标记。
4. 跟踪任务标识、规范结果与回报。发送成功、进程空闲和业务完成分别判断，不能由 `idle/done` 推断票已完成。
5. 新的独立任务使用新 worker 或 griller。关闭旧面板前确认结果已落盘、写入已停止，并更新台账状态；尚未完成的并行会话不受影响。简单模式合并后端的主会话保持原位。

同一票内 TDD 迭代和功能自测属于当前任务。当前流程决定新的独立返修任务时，新开适当 worker，并交付问题与代码引用，不依赖旧会话记忆。

## 子会话主动回报

Herdr 已有派工控制面，不要求另写调度守护进程。父会话创建子面板时必须给出自身可寻址的 agent 名称或 pane ID，以及唯一任务标识。

子会话完成所需用户交互并将结果写入规范文件后，使用经过验证的 `herdr agent prompt <父地址> <结果消息>` 回报。消息至少包含：

```text
HERDR_RESULT task=<本票标识> status=<completed|blocked|failed>
role=<执行身份> result=<结果文件/票据引用>
summary=<简短结果或阻塞问题>
```

这是本技能的消息约定，不是 Herdr 内置事件。回报不得声称未完成的用户确认、测试或提交已完成。图形 notification 只是给人的提示，不能代替向父 agent 投递消息。

父会话收到回报后核对任务、结果路径和完成条件，再更新状态及关闭已完成面板。wayfinder 的秘书随后选择下一就绪票、创建新面板并发送 prompt；需要用户回答的 grilling 在新面板内进行，秘书不代答。重复回报不得重复派票；已认领或进行中的票不重开。

父会话正处于权限或问题 UI 时，不盲发确认键。回报被阻塞或超时，先检查当前目标与输出，保留已落盘结果；不要假定消息未送达而无限重发。无法验证父会话可接收消息时，说明自动衔接缺少的能力；不能把手动转贴假称全自动。

## 匿名与原生执行

`background` 使用配置工具的新非交互执行，不创建 Herdr 面板。reviewer/checker 始终使用该载体。调用方按原流程启动、等待或收集结果，保留原来的并发与汇总方法。

`native` 仅用于明确配置的 searcher/merger；必须核实宿主实际能提供所选工具、模型和思考等级。不能仅用角色标签把其他工具的任务交给当前宿主子 agent。能力不匹配时，将具体替代配置交秘书确认。

- 新匿名执行只接收必要文档、代码和命令，不继承开发对话，不恢复旧匿名会话。
- 运行期间可以使用必要临时句柄等待结果；长期归档不记录匿名 session ID 或句柄，结束后不复用。
- 工具提供无持久化选项时使用；没有时不能宣称宿主已删除历史。报告和交付物可以保留。
- `research` 的 searcher 直接执行研究；review 叶执行者只处理自己的视角。不得重复启动只会再委派同一工作的空层。
- checker 返回实际命令退出码；reviewer 返回指定范围的发现；merger 返回授权范围的合并结果。后续决策回到父工作流。

## 权限与失败

worker 可读本地代码、编写测试并自测功能；独立构建、编译、静态检查交 checker。外部搜索交 searcher，读取已有文件和日志不算外部搜索。

设计、研究、原型资料的 Git 操作由秘书负责；正式开发的提交、合并及重启由 PM 负责，merger 仅执行其明确授权的集成。不得通过关闭面板抛弃未交接修改。

缺少工具、模型、权限或必要配置时报告具体缺口，不擅自替换。职责由 skill 约束；本包没有实现命令拦截、进程隔离或另一个开发调度服务。
