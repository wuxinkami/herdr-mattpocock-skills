# Herdr 任务归档

## 文件位置与 recap

默认：`.agents/herdr/session/<YYYYMMDD-HHmmss>-<秘书recap中文简称>.md`。目录取 `docsDir`，文件基名遵循本页规则；不移动或改名既有历史记录。

1. 只使用**当前秘书会话**的 recap，不能取最后活跃的 PM、worker 或其他会话标题。
2. 有经本机验证的原生 recap 读取方式时，使用返回内容，并记录方式和来源。Codex 会话名称、Claude `/rename` 显示名称不自动等同于 recap。
3. 原生读取不可用或尚未验证时，由秘书在当前设计上下文形成一行 recap，再提炼中文简称；标记 `secretary-generated` 和“原生 recap 自动提取未实现”。不编造 CLI 命令、不扫描猜测的私有会话数据库。
4. 文件名保留中文，替换路径分隔符、控制字符及文件系统禁用字符（如 `<>:"/\\|?*`），去除末尾空格和点，禁止 `.`、`..` 等路径跳转。长 recap 使用简短中文标题，文档内保留原文；空标题重新提炼，不生成无标题记录。
5. 时间戳采用项目约定时区；未约定时用用户本地时区，在文档中记录时区或 UTC 偏移。同名时追加 `-2` 等唯一后缀，不能覆盖已有文件。

例：`.agents/herdr/session/20261117-143052-餐厅点单系统.md`。这是格式示例，不是本轮已经创建的记录。

本包目前规定标题获取与命名协议，不包含跨 Codex/Claude 的原生 recap 自动提取器。后续本地读取器可以提供当前秘书 recap 作为输入，必须保留来源区别；读取到会话名时先标明 `native-session-name`，由秘书据此生成 recap，不能冒充原生 recap 输出。

## 创建、确认与交接

秘书使用 [记录模板](../templates/session-log.md) 创建本轮文件。wayfinder 设计阶段如需登记 griller，可先创建，开工配置状态保持“待确认”；设计完成后使用同一文件，补齐配置并请用户确认。也可在进入实现前创建，再补录真实的设计会话。不得把已有设计活动写成实现配置已确认。

进入实现前，秘书按 [确认模板](../templates/kickoff.md) 展示身份表。用户确认后，将**实际展示且确认的整张表**、确认时间和准确简记保存；只有此后才能新开 PM。交接包含该文件路径、已确认配置快照、选定流程及规范文档入口。PM 读取后直接执行，不重新请用户确认同一配置。

简单模式不新建 PM，但同样由秘书身份完成展示与归档，再进入实现。秘书和 PM 合并时直接更新当前记录，无需发送内部交接消息。

确认后路径固定。秘书 recap 后续变化可记在文档内，不能自动改名导致 PM 的引用失效。本轮配置发生变化时，秘书追加用户确认的修订；保留原快照及其生效范围。

## 两种表不要混淆

| 记录 | 内容 | 行数规则 |
| --- | --- | --- |
| 身份配置快照 | 每个身份的用途、工具、模型、思考等级、载体；未用身份也明确标记 | 与展示的确认表一致，包含匿名身份 |
| 显式会话台账 | 实际 session ID、工具、身份、子任务标题、Herdr 位置和状态 | simple 两行；complex 每个实际显式会话一行 |

秘书登记自身及设计会话，PM 更新实现会话；关闭面板只改状态，不删除其历史条目。simple 两行按主会话、前端分组；同一轮更换前端时，将旧工具、ID 和子任务标题紧凑保留在前端同一行，当前位置记录现任面板，不增加数据行。通常每行只有一个会话。

只有真实原生会话 ID 可写入 `session_id`，获取不到则记录原因。Herdr pane ID 单列；匿名执行的 ID 和临时句柄不归档，必要的报告可以保留。

归档引用 canonical map、spec、tickets、检查与审查报告，不复制整段上下文，也不成为另一份产品事实来源。
